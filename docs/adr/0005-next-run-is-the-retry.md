# The next Sync Run is the retry mechanism; there are no in-run retries

A failed API call is not retried inside the Sync Run: transient Keycloak or Outline errors are logged, and the next Sync Run — at most one `SYNC_INTERVAL` later — reconciles the delta, which is safe because every run is idempotent. A run that trips Outline's rate limits (1000 requests/60s, `groups.create` 10/min per credential) simply does less work and converges over successive runs, so the initial sync of a large client may take several intervals instead of one long run. Every request still has a 30s timeout, a failed Keycloak read aborts before any Outline write, and `--once` exits non-zero so an external scheduler can retry. Generic 5xx backoff was rejected because it mostly buys latency and retrying a timed-out `groups.create` can create a duplicate group when the first request actually landed; `Retry-After` retries on 429 were rejected because the limit window resets within a default interval and self-hosters can raise `RATE_LIMITER_MULTIPLIER` or `RATE_LIMITER_REQUESTS` for a large first sync.
