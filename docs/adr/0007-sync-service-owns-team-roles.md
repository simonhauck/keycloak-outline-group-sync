# The Sync Service owns Team Roles full-state with a Viewer fallback

The service reconciles the Team Role of every Managed Account — an Outline Account matched by email to exactly one Keycloak user — setting the highest Role Signal held in the order Admin > Member > Viewer > Guest, and the Fallback Team Role (`Viewer` by default) when none match. Full state was chosen because revocation must work the same way as group membership, and scoping the sync to current signal holders would leave a stale Team Role behind when the last signal is removed. `Guest` was rejected as the default fallback because Outline Community cannot assign it without the Guests entitlement, and `Member` would leave every unmatched user with edit rights. This amends ADR-0004: the service changes team roles now, but still never creates, invites, suspends or deletes accounts, and it skips the token owner's account because Outline forbids self-role-change. Consequence: every Managed Account gets a computed Team Role on every Sync Run, so deployments must configure their Role Signals; a configured signal that does not exist on the roles client aborts the Sync Run before any Outline write rather than silently demoting everyone.
